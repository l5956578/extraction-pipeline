**Yes — this is a strong, common pattern in agentic coding (coder + vision critic loop).** It directly attacks the fatigue you’re describing.

### Quick assessment + improvements / safeguards

**What’s already good**
- Clear separation of concerns: coding agent proposes, Vision QA only *describes* mismatches against the ground-truth PNG + rules. No prescribing fixes.
- Explicit escalation after 4 attempts.
- Post-fix reporting protocol.
- Intention to put the comprehensive rules in a file the QA agent can always see.

**Improvements I recommend baking in**
1. **Single source of truth rules file**  
   Create (or extend) something like `references/extraction-invariants.md` (or whatever your existing rules file is called). Every layout rule, callout placement heuristic, prose purity rule, table rendering requirement, ID cleanliness rule, “no trash soup after figures”, blank-row-for-MD-tables, etc. lives there. Both the coding agent and the QA agent load it.

2. **Structured QA output contract**  
   Force the Vision agent to return:
   ```yaml
   status: pass | fail
   failures:
     - page: 41
       element: callout / prose-block / table / figure-caption / ...
       severity: critical | major | minor
       visual_observation: "..."
       md_observation: "..."
       rule_violated: "callout-placement-exception-when-adjacent-prose-is-full-width"
   ```
   This makes the loop machine-readable and prevents vague “looks wrong” comments.

3. **Snapshot discipline**  
   The skill must define *exactly* how the coding agent produces the full-page PNG the QA agent sees (PDF page render at known DPI + the corresponding Markdown rendered to HTML → PNG, or side-by-side). Without a deterministic snapshot method the loop becomes non-reproducible.

4. **Hard non-interference rule**  
   The QA skill must explicitly say: “You are a pure observer. Never suggest code changes, never rewrite Markdown, never propose architecture. Describe only.”

5. **Scope guardrail**  
   The skill should only be invoked for *deterministic extraction defects* (placement, merging, soup, IDs, formatting loss, missing blank rows, etc.). Design decisions stay with you.

6. **Integration with existing pipeline**  
   The skill must not invent a new extraction path. It must sit on top of whatever 3-pass / inventory / cleanup architecture you already have documented in `agents.md` / `context.md` / pipeline docs.


These keep the system from drifting and make the skill safe to leave running autonomously.
